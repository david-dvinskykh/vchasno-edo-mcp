# Вчасно.ЕДО MCP Server

MCP-сервер (Model Context Protocol) для сервиса электронного документооборота **Вчасно.ЕДО** (`edo.vchasno.ua`), написанный на **Go**.

Даёт LLM-агенту (Claude, GPT, Open WebUI и др.) полный доступ к публичному API v2: исходящие и входящие документы, загрузка и отправка, подписание (готовым .p7s или облачным ключом Вчасно.КЕП), внутреннее согласование, ярлыки, дополнительные параметры, архив, структурированные данные, публичные ссылки, шаблоны и сценарии, команды, права сотрудников, тарифы и отчёты о действиях.

**Интерфейс авторизации — тот же, что в [bas-corp-mcp](https://github.com/david-dvinskykh/bas-corp-mcp):** OAuth 2.1 + PKCE + динамическая регистрация клиентов, зашифрованные JWT, режим заголовков и pre-auth через переменные окружения. Одна и та же настройка MCP-клиента подходит обоим серверам.

| | |
|---|---|
| Инструментов | **92** (реализованы все методы API v2) |
| Ресурсов | 8 справочных + шаблон `vchasno://document/{id}` |
| Промптов | 9 готовых сценариев |
| Бинарник | один статический файл ≈ 12 МБ |
| Память | ≈ 20–30 МБ RSS |
| Зависимости | только `modelcontextprotocol/go-sdk` |

### Три вещи, которых нет в «сыром» API

1. **Коды переводятся в смысл.** Статус `7004` приходит вместе с `status_meaning: "Signed by the owner, waiting for the counterparty"`, `category: 2` — вместе с `category_title: "Рахунок"`, сумма в копейках — вместе с `amount_uah`. Агенту не нужно держать таблицы кодов в голове.
2. **Везде, где API хочет GUID, принимается человеческое имя.** Сотрудник — по email, ярлык — по названию, команда — по названию, тип документа — по заголовку. Разрешение идёт через кэш справочников компании (TTL 10 минут).
3. **Опасные действия требуют подтверждения.** `delete_document`, `reject_document`, `delete_role`, `reset_user_tokens`, `revoke_public_link`, `cloud_sign_document`, `activate_integration_trial` и остальные необратимые инструменты отказываются работать без `confirm=true` — модель не может удалить документ «между делом».

### Подписание
- **Готовым .p7s** — `add_signature` (base64). Приватных ключей сервер не видит никогда.

- **Чужому человеку без аккаунта** — `create_sign_session` (именная сессия) или `create_public_link` (ссылка).

### Файлы
`download_document` с `format`: `original` · `archive` (ZIP с подписями и инструкцией проверки) · `p7s` · `asic` (евро-подписи) · `pdf` · `xml_pdf`. Плюс `get_download_links`, `upload_document_version`, `delete_document_version`.

## Запуск

```bash
go build -o vchasno-edo-mcp ./cmd/vchasno-edo-mcp

# 1) Pre-auth: один токен на весь сервер
MCP_VCHASNO_TOKEN='<ваш токен Вчасно>' MCP_PORT=8088 ./vchasno-edo-mcp

# 2) OAuth: каждый клиент вводит свой токен на странице входа
MCP_PORT=8088 MCP_ISSUER_URL=https://vchasno-mcp.example ./vchasno-edo-mcp
```

Токен создаётся в кабинете «Вчасно» в настройках сотрудника ([инструкция](https://docs.google.com/document/d/1bvKIvpfyizFUv-acC0e22O8ufeRkwwjeur5qufzWF70/edit)) и связывает **пользователя + компанию**.

### Переменные окружения

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `MCP_HOST` / `MCP_PORT` | `0.0.0.0` / `8080` | Адрес прослушивания |
| `MCP_ISSUER_URL` | `http://localhost:<port>` | Публичный URL сервера (issuer в OAuth и JWT) |
| `MCP_VCHASNO_URL` | `https://edo.vchasno.ua` | Хост API |
| `MCP_VCHASNO_TOKEN` | — | Токен для pre-auth режима |
| `MCP_HEADER_URL` / `MCP_HEADER_TOKEN` | `X-Vchasno-URL` / `X-Vchasno-Token` | Имена заголовков режима «токен в заголовке» |
| `MCP_JWT_KEY_DIR` | `.` | Где хранится RSA-ключ (токены переживают перезапуск) |
| `MCP_JWT_EXPIRY_DAYS` | `365` | Срок жизни выданного токена доступа |
| `MCP_READ_ONLY` | `false` | `true` — регистрируются только читающие инструменты |
| `MCP_MAX_RPS` | `8` | Своё ограничение частоты (у Вчасно — 10 запросов/с на компанию) |
| `MCP_MAX_PAGE_SIZE` / `MCP_DEFAULT_PAGE_SIZE` / `MCP_MAX_PAGES` | `100` / `25` / `20` | Пагинация |
| `MCP_MAX_UPLOAD_MB` | `15` | Предел размера файла (как у сервиса) |
| `MCP_DOWNLOAD_DIR` | системный temp | Куда складываются скачанные файлы |
| `MCP_ALLOW_LOCAL_FILES` | `true` | Разрешить `file_path` при загрузке (иначе только base64) |
| `MCP_API_TIMEOUT_SEC` / `MCP_RETRY_ATTEMPTS` | `90` / `3` | Таймаут и число попыток |
| `MCP_LOG_LEVEL` | `info` | `debug`, `info`, `warn`, `error` |

### Три режима авторизации

1. **Pre-auth** — задан `MCP_VCHASNO_TOKEN`, все клиенты работают в контексте одной компании, OAuth не нужен.
2. **Заголовки** — клиент шлёт `X-Vchasno-Token` (и при необходимости `X-Vchasno-URL`).
3. **OAuth 2.1** — клиент получает `401` с `WWW-Authenticate`, находит метаданные, регистрируется (RFC 7591), открывает страницу входа, вставляет токен «Вчасно». Токен доступа — JWE(RSA-OAEP-256, A256GCM) поверх JWS(RS256): подпись доказывает, что токен выдал этот сервер, шифрование скрывает токен «Вчасно» от самого MCP-клиента, который его хранит.

### Эндпоинты

`/mcp` (Streamable HTTP) · `/health` · `/ready` · `/mcp/openapi.json` · REST-мост `/tools`, `/tools/{name}`, `/resources`, `/resources/read`, `/prompts`, `/prompts/{name}` — для клиентов без MCP (Open WebUI, curl).

## Тесты

```bash
go test ./...          # 96 тестов
go test -race ./...
./scripts/smoke.sh     # живая проверка запущенного сервера
```

Покрыто:

- **`internal/vchasno`** — парсинг сумм (копейки ↔ гривны), словари статусов, сборка query-строк, ретраи на 429, отсутствие ретраев на 403, заголовок авторизации, работа ограничителя частоты, отсутствие утечки токена в логи.
- **`internal/auth`** — round-trip токена, невозможность прочитать из него токен «Вчасно», отказ чужому issuer, истёкший токен, PKCE (правильный/неправильный verifier, отказ `plain`), переживание перезапуска, экранирование страницы входа.
- **`internal/tools`** — 53 сценария против встроенного мока API (`internal/mockvchasno`), который воспроизводит машину статусов, курсорную пагинацию, флаги `has_changed` и `processed`, документированные коды ошибок и лимит частоты: полный цикл «загрузил → подписал → отправил», конвертация сумм, разрешение email/названий в id, обязательность `confirm`, отказ править реквизиты с 7003, отказ подписывать в 7000, все форматы скачивания, публичные ссылки, архив, импорт подписанного, отчёты, режим `MCP_READ_ONLY`, поведение при отсутствии тарифа, все ресурсы и промпты.
- **`internal/httpserver`** — три режима авторизации, полный цикл OAuth (регистрация → страница → код → обмен с PKCE → вызов `/mcp`), одноразовость кода, отказ при неверном verifier, REST-мост, OpenAPI.

### Живая проверка на проде

Прогнано на реальной базе `edo.vchasno.ua` (тариф «Інтеграція (пробний)»), режим `MCP_READ_ONLY=true` — ничего не отправлялось, не удалялось и не менялось:

- `self_check deep` — **13 из 13** проверок зелёные: 4 активных тарифа, 2 сотрудника, 10 исходящих, 144 входящих, 48 типов документов, 5 файловых шаблонов, 16 запросов на удаление, 11 комментариев за 30 дней.
- **22 читающих инструмента** — списки, фильтры по статусу и сумме, инкрементальная синхронизация, проверка контрагента, курсорная пагинация.
- **15 инструментов по конкретным документам** — досье с `full=true`, подписи, комментарии, согласование, публичные ссылки, ссылки на скачивание.
- **Скачивание** — файлы проверены `file(1)`: оригинал (PDF 1.3, 2 стр.), подписанный архив (ZIP: оригинал + два `.p7s` + квитанция + инструкция), контейнер подписи (DER PKCS#7), печатная форма (PDF 1.7, 3 стр.).
- **Все 8 ресурсов** отдаются и наполнены живыми данными компании.

Живая проверка нашла пять расхождений между документацией и сервисом — все обработаны и закрыты регрессионными тестами:

1. `POST /billing/companies/rates/trials` отвечает `201` с телом `201: Created` (не JSON) — клиент считал успешный вызов ошибкой. Теперь тело декодируется только когда оно похоже на JSON.
2. `GET /documents/comments` отвечает `400 invalid_request`, если не передать **оба** конца периода; в документации это не упомянуто. `list_comments` подставляет последние 30 дней и говорит об этом в ответе.
3. `GET /download-documents` отдаёт `status` строкой, а `ready`/`pending` числами `1`/`0` — вместо документированных int и bool. Эти поля теперь декодируются терпимо к обеим формам.

### Живой цикл записи

Отдельно прогнан полный цикл записи на реальной базе — на служебном тестовом документе **без контрагента** (статус 7000, никуда не отправлялся), с удалением в конце:

- `upload_document` → статус 7000, сумма `123.45` грн доехала как `12345` копеек и вернулась как `amount_uah`, `vendor_id` сохранился и находится фильтром.
- `get_document full=true`, `get_document_statuses`, поиск по `vendor_id` — документ читается всеми способами.
- `update_document_info` — название, номер и сумма изменены (разрешено ниже 7003).
- `add_comment internal=true` — комментарий записан и прочитан обратно.
- `download_document format=original` — скачанные байты **побитово совпали** с загруженными (SHA-256).
- `delete_document` без `confirm` — отказ; с `confirm=true` — удалён, `get_document` отвечает 404.

После прогона аккаунт вернулся в исходное состояние: 10 исходящих документов, поиск по `vendor_id` пуст.

Цикл нашёл ещё два расхождения:

4. Живое название типа 15 — **«Інший»**, а в документации API — «Інше». Теперь принимаются оба написания, но **только точные**: подстрочное совпадение убрано, потому что «Рахуно» является подстрокой «Розрахунок коригування» — молча поставить документу не тот тип хуже, чем отказать. На близкий промах инструмент отвечает списком кандидатов: `unknown document type "Рахуно" (did you mean: 2 — Рахунок; 23 — Розрахунок коригування)`.
5. `POST /documents/<id>/version` отвечает `201`, но версия не появляется — ни на обычном документе, ни на загруженном с `is_versioned=true`. Причина на стороне сервиса. Инструмент больше не докладывает об успехе вслепую: он перечитывает документ и возвращает `versions_now`, а при нуле — явное предупреждение.

Отправка документов контрагентам, подписание живым ключом и удаление чужих документов на проде **не прогонялись** — это ушло бы третьим лицам. Они покрыты 53 сценариями против встроенного мока, включая полный цикл «загрузил → подписал → отправил».

## Тариф «Інтеграція»

API Вчасно закрыт для компании без активного тарифа **«Інтеграція»** или **«AI Інтеграція»** — любой метод отвечает `403 access_denied`. Сервер это различает: он стартует, `self_check` и `get_billing` объясняют, чего не хватает, а остальные инструменты отказываются сразу с понятной подсказкой вместо голого 403.

Разовый 30-дневный тестовый тариф включается методом `activate_integration_trial` — **один раз за всё время существования компании**, поэтому инструмент требует `confirm=true`.

Важно: состояние тарифа определяется при подключении. Если тариф включили, пока сервер работает, его нужно перезапустить — иначе сессия продолжит считать API закрытым.

## Ограничения сервиса

- 10 запросов в секунду на компанию (общий лимит на все её интеграции).
- Одна загрузка: до 500 файлов, суммарно 100 МБ, один файл до 15 МБ.
- Форматы: PDF, XML, DBF, TXT, PNG, JPEG, DOCX (DOC), XLSX (XLS), RTF.
- Отчёт о действиях: период до 30 дней, не глубже года назад.
- Суммы в API — целые числа в копейках (сервер принимает гривны и добавляет `amount_uah` в ответы).
